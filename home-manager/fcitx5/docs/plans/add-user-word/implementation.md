# 快速添加用户词：实现计划

状态：已实现并通过构建与隔离验证；尚未切换当前系统。使用说明见 [快速加词](../../add-user-word.md)。以下保留实现设计与验收记录。

## 目标与边界

提供 `xhup-add-word` 和 `Mod+Ctrl+X`，完成“输入词语 → 检查编码 → 保存 → 请求 Rime 部署”。日常添加词语不需要重新构建 NixOS；首次安装工具和修改启动配置需要构建、应用配置。

维护现有四份文本用户词库，默认写入 `dictionaries/xhup.user.dict.yaml`，可选 work、coding、chat。当前方案关闭了自动用户词库学习，因此不向 Rime userdb 写入。第一版不做批量导入、删词管理或自动 Git 提交，不改上游码表和生成的计算机词库。

## 交互流程

1. **词语输入**：快捷键打开普通 wofi dmenu，默认输入框留空，用户手动输入或粘贴。仅命令行明确指定的词语会预填；不自动读取剪贴板。
2. **编码输入**：展示词语、建议读音和编码，编码可直接编辑。已有词语优先提供已收录编码；新词使用现有小鹤编码规则生成建议。
3. **确认页**：展示词语、读音、编码、目标词库、重码候选及来源；默认选项为“保存并部署”。另提供“修改编码”“修改读音并重新编码”“切换词库”“仅保存”“取消”。没有重码也保留这一步。

默认只需提交词语、提交编码、确认保存。分类选择不是必经步骤。Esc 在写入前退出，不改词库、不部署。写入完成后不再把关闭窗口解释成撤销。

新增独立入口，不修改现有 `Mod+X` 码表和 `Mod+Shift+X` 查码行为。第一版使用标准 wofi 的多步对话，不扩展实时查码的 C 补丁；按回车切换步骤，但最终保存前会显示编码与冲突信息。

## 编码、重复与排序规则

| 情况 | 处理 |
| --- | --- |
| 双字词 | 两个字各取双拼两码 |
| 三字词 | 前两字各取首码，末字取双拼两码 |
| 四字及以上 | 前三字及末字各取首码 |
| 单字 | 选择已有码表编码或手填；不凭拼音生成音形全码 |
| 多音词 | 优先现有词典注音，再用 pypinyin；展示读音供修正 |
| 不支持自动编码的文本 | 允许手填编码，不悄悄丢弃字符后生成 |
| 同词同码已存在 | 在所有启用词库中查重，提示来源，不追加 |
| 同词不同码 | 明示为新增别码，确认后允许添加 |
| 同码不同词 | 展示候选、权重、来源；确认后共存，不覆盖旧词 |

复用现有编码器的 zh/ch/sh、ü 和中英混合词规则；修改读音时校验读音数量与词语相符。建议与用户手填值明确区分。

校验词语为非空单行文本，去掉首尾空白，拒绝制表符、换行、NUL 和控制字符；第一版长度上限 128 个 Unicode 字符。内部空格和标点保留，需要时要求手填编码。编码统一小写，限 `[a-z]{1,4}`。

新增条目默认权重 `100`，与现有手工词库一致。重码预览按查码工具的匹配/权重规则排列，但不把该顺序承诺为 Rime 实际候选顺序，也不承诺新词首选。第一版不额外提供调频界面。

## 文件写入与恢复

- 目标只允许四份用户词库，读取实际启用的导入表进行查重。目标缺失、未启用、表头不符或不可写时，给出明确错误，不另建一个未被导入的同名文件。
- 解析 Home Manager 符号链接后写真实源文件，保留用户目录中的链接。不能直接对链接路径执行替换，否则会断开仓库与运行目录的关联。
- 以现有内容为基础追加 `词语<TAB>编码<TAB>100`，只定点更新头部 `version` 为新的唯一字符串，保留其他注释、顺序及已有条目，不用 YAML 序列化重写全文。
- 使用按目标仓库区分的进程锁，阻止工具自身并发写入。确认页记录文件摘要；保存前重新读取并查重，若外部修改导致预览失效，返回确认页。此锁不宣称能约束不配合的外部编辑器。
- 替换前将原文件备份到 `$XDG_STATE_HOME/xhup-add-word/backups/`（默认 `~/.local/state/...`）。在真实目标同目录写临时文件，保留权限、刷新文件、原子替换并刷新目录；失败时清理临时文件并报告所处阶段。
- 部署失败保留已保存词语与备份，提供重新部署入口；不自动回滚整个词库，以免覆盖后续编辑。

## 部署接口与启动问题

当前排查快照显示：占用 `org.fcitx.Fcitx5` 的是旧版桌面自启动实例，Home Manager 的 `fcitx5-daemon.service` 处于 inactive。实现时需重新检查现场，先解决实例归属，再验证加词生效。

1. 以 Home Manager 用户服务作为唯一启动入口。核对实际 XDG desktop 文件名后，通过用户级同名 `Hidden=true` 覆盖禁用重复自启动；检查 niri 没有另一个启动命令。
2. 配置应用时进行一次受控交接：停止旧自启动实例，等待 D-Bus 名称释放，再启动 Home Manager 服务。此操作不放在每次加词流程中。
3. 加词工具从 D-Bus 获取 owner PID，比较 `/proc/PID/maps` 加载的 Rime 插件路径与 Nix 注入的预期路径；同时核对用户词库目录。只比较 fcitx5 版本或服务 active 状态不够。无法核实时允许明确选择“仅保存”，不自动重启正在使用的输入法。
4. 保存后向现有实例的 Controller `SetConfig` 发送部署请求。不要用 `fcitx5-remote -r` 代替，后者只重载 Fcitx 配置。

当前版本源码及隔离测试验证的调用为：

```bash
busctl --user call org.fcitx.Fcitx5 /controller \
  org.fcitx.Fcitx.Controller1 SetConfig sv \
  fcitx://config/addon/rime/deploy 'a{sv}' 0
```

URI 分派、Rime `setSubConfig("deploy", ...)` 和空配置 variant 的命令行编码均已通过真实隔离集成测试。实现使用参数数组调用子进程并设置超时，不拼接 shell 文本。

部署是异步的。请求成功后提示“已保存，已请求部署”，由 Fcitx/Rime 原生通知报告部署成功或失败；D-Bus 返回不等于词语已生效。请求失败则提示“已保存，部署请求失败”及重试命令。请求超时属于结果未知，不自动反复触发部署。

## 命令行接口

```bash
# 默认进入 wofi 流程
xhup-add-word

# 只计算编码、查重并输出预览，不写入、不部署
xhup-add-word add '示例词语' --dry-run

# 指定编码和分类，无交互保存并请求部署
xhup-add-word add '示例词语' --code ulcy --category work --yes

# 仅保存；之后可单独重试部署
xhup-add-word add '示例词语' --code ulcy --yes --save-only
xhup-add-word deploy
```

`add` 未指定 `--yes` 或 `--dry-run` 时进入确认流程。分类默认 common。示例编码仅说明参数形式，不作为测试词自动写入。

明确输出状态：`cancelled`、`already_exists`、`saved_only`、`deploy_requested`、`saved_deploy_failed`。退出码 0 表示操作按选择完成或无需追加，不表示异步部署完成；参数/校验错误为 2，写入失败为 3，已保存但部署请求失败为 4。取消返回 0，并通过状态与成功写入区分。

运行依赖：Python（PyYAML、pypinyin）、标准 wofi、systemd 的 busctl、libnotify。查码工具仍使用私有补丁版 wofi 和 wl-clipboard。

**Nix 打包注意**：当前包装器将单个 Python 文件放入 store，新增相邻模块后不能沿用这种方式直接导入。将相关脚本和共享模块打包在同一个目录，或构建统一 Python 包；构建期生成器和运行期工具都使用同一份模块。无需为本功能修改 flake 输入。
